Chapter 16

Bettercap MITM

ARP spoofing, HTTPS stripping, and credential interception from the attacker's perspective. How Wazuh detects the ARP changes and what the defender sees in logs.
Lab Environment Only
Bettercap is a powerful network attack tool. It must only be used in the isolated lab environment against lab VMs. ARP spoofing on a production network disrupts connectivity for all users on that subnet and is illegal without explicit written permission.

Learning Objectives

  • Explain what ARP spoofing is and how it positions an attacker as a man-in-the-middle
  • Describe how Bettercap's HTTPS stripping module downgrades HTTPS to HTTP
  • Run a controlled Bettercap ARP spoof in the lab and observe the resulting Wazuh alert
  • Read the Wazuh ARP spoofing alert and identify the attacker MAC and IP
  • Identify the Sophos firewall log anomalies that appear during an active MITM attack
  • Describe how HSTS prevents HTTPS stripping and why it matters

How ARP Spoofing Works

ARP (Address Resolution Protocol) maps IP addresses to MAC addresses on a local network. When a host wants to send traffic to a gateway, it broadcasts "who has IP 10.0.1.1?" and the gateway responds with its MAC address. The host caches this mapping in its ARP table.

In an ARP spoofing attack, the attacker sends unsolicited ARP replies to the victim and the gateway, claiming that the attacker's MAC address is the MAC for both. Both parties update their ARP caches with the forged entries. All traffic between the victim and gateway now flows through the attacker.

ARP Spoofing: Before and After
After ARP poisoning, all victim traffic routes through Bettercap before reaching the gateway. The victim sees no disruption because Bettercap forwards the traffic.

Wazuh ARP Spoofing Alert

Wazuh monitors ARP traffic and compares ARP replies against a learned MAC-to-IP mapping table. When an ARP reply claims a different MAC for a previously-seen IP, Wazuh fires rule 2502.

Wazuh Alert - ARP Spoofing Detected (Rule 2502)
{ "timestamp": "2026-09-20T11:05:44.102Z", "rule": { "id": "2502", "description": "ARP spoofing detected: IP claimed by new MAC", "level": 9, "groups": ["arp", "network", "mitm"] }, "data": { "arp.ip": "10.0.0.1", "arp.mac_old": "11:22:33:44:55:66", "arp.mac_new": "AA:BB:CC:DD:EE:FF", "interface": "eth0" }, "agent": { "name": "victim-workstation", "ip": "10.0.0.5" } }

The arp.mac_old is the legitimate gateway MAC. The arp.mac_new is the attacker's MAC. Cross-reference the new MAC against your DHCP lease table or switch MAC address table to identify which physical port the attacker is connected to.

HTTPS Stripping with Bettercap

Once positioned as a MITM, Bettercap can run its http.proxy module with HTTPS stripping enabled. When the victim's browser tries to connect to an HTTPS site, Bettercap intercepts the request and responds over plain HTTP, while maintaining an HTTPS connection to the real server. The victim's browser sends credentials over HTTP that Bettercap reads.

Bettercap HTTPS Stripping Attack Flow
The victim's browser sends credentials in plain HTTP because Bettercap stripped the HTTPS. The server logs show a normal successful login with no indication of compromise. The attacker has the credentials.

Lab Commands

# Start bettercap on the attacker's Kali VM (lab only) $ sudo bettercap -iface eth0 # Inside bettercap interactive console: # Enable ARP spoofing targeting victim and gateway bettercap > set arp.spoof.targets 10.0.0.5 bettercap > set arp.spoof.fullduplex true bettercap > arp.spoof on # Enable HTTPS stripping proxy bettercap > set http.proxy.sslstrip true bettercap > http.proxy on # Sniff for credentials in plaintext bettercap > net.sniff on # What you see in bettercap output when victim logs in: [net.sniff.http.request] POST http://login.example.com/auth username=admin&password=P%40ssw0rd%21

Key Takeaways

  • ARP spoofing poisons the ARP caches of the victim and gateway, routing all traffic through the attacker. The victim typically does not notice because the attacker forwards all traffic.
  • Wazuh detects ARP spoofing when an IP address is claimed by a different MAC than previously seen. The alert includes both the old (legitimate) and new (attacker) MAC addresses.
  • HTTPS stripping downgrades the victim's HTTPS connection to plain HTTP, exposing credentials. The attack is only possible if the target site does not use HSTS.
  • HSTS (HTTP Strict Transport Security) is the most effective defence against HTTPS stripping. If a site sends the Strict-Transport-Security header, the browser will refuse to connect over plain HTTP.
  • During an active MITM attack, SafeLine WAF logs may be absent because the victim's traffic no longer flows through the normal network path. Wazuh and Sophos ARP/flow logs are the primary evidence sources.
