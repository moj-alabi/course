Chapter 17

IR Triage to Ticket

The complete incident response workflow: from first alert to closed ticket. Triage methodology, evidence collection, containment actions, and professional ticket documentation.

Learning Objectives

  • Apply a structured triage process to a new Grafana alert in under five minutes
  • Collect and preserve the minimum evidence set required to write a complete ticket
  • Execute the correct containment action for each attack category
  • Write a clear, precise incident ticket that meets professional SOC standards
  • Identify when to escalate an incident beyond tier-1 response
  • Close a ticket correctly with evidence, timeline, and recommended remediation

The IR Lifecycle

Incident Response Lifecycle
The six-stage IR lifecycle. Triage and containment are time-critical. Investigation and remediation can be more methodical. Always document throughout.

Five-Minute Triage Checklist

When a new alert appears in Grafana, run through this checklist before touching any tool. Discipline here prevents wasted time chasing false positives and ensures you do not miss a genuine incident.

StepQuestionWhere to LookTime Budget
1. Read the alertWhat is the rule ID, level, and description?Grafana alert table or Wazuh alert JSON30 seconds
2. Identify sourceWhat is the source IP? Internal or external?data.srcip field in Wazuh alert30 seconds
3. Check threat intelIs the source IP known malicious?VirusTotal / AbuseIPDB lookup60 seconds
4. Scope the incidentWhat else has this IP done? How many hosts?Sophos Firewall log, SafeLine WAF log filtered by src_ip90 seconds
5. Assess severityIs this a false positive, probe, or active attack?Combination of rule level, attack type, and scope60 seconds
6. Decide actionBlock, escalate, monitor, or close as FP?Use the containment reference table below30 seconds

Writing a Professional Incident Ticket

Every incident must be documented in a ticket. A complete ticket allows any analyst to pick up the investigation, provides an audit trail, and is required for breach notification and insurance claims.

Incident Ticket Anatomy
A complete incident ticket. Summary, timeline, evidence, and actions taken are the four mandatory sections. Every timestamp is UTC. Every claim references a specific log entry.

Ticket Field Reference

FieldRequired ContentCommon Mistakes
TitleAttack type + affected asset + date. Example: SSH Brute Force - web-server-01 - 2026-09-20Vague titles like "suspicious activity" make searching impossible
PriorityP1=Active compromise. P2=Confirmed attack, contained. P3=Suspicious, investigating. P4=InformationalDefaulting everything to P2. Calibrate to actual impact.
SummaryOne to two sentences. What happened, who did it, what was affected, what action was takenWriting a paragraph of background theory instead of the facts
TimelineEvery event in timestamp order, UTC. Source tool, field names, field values for each entryWriting "around 10am" instead of exact timestamps from logs
EvidenceList every log source queried. Name specific alert IDs, file attachments, screenshotsWriting "checked the logs" without specifying which log, which query, which result
Actions TakenWhat was blocked, isolated, reset, or escalated. By whom. At what timestamp.Leaving this section blank. If you acted, document it.
Recommended RemediationWhat needs to happen to fully resolve the root cause. Who owns it.Closing tickets without documenting the underlying vulnerability

Escalation Decision Tree

When to Escalate Beyond Tier-1
The core escalation question is: did anything succeed? A blocked attack that never got through is Tier-1. A successful login, SQLi response, or exfiltration bytes is always Tier-2.

Key Takeaways

  • Apply the five-minute triage checklist before touching any tool: read the alert, identify the source, check threat intel, scope the incident, assess severity, decide action.
  • Containment must come before investigation. Block the attacker, isolate affected hosts, and reset credentials before spending time building the full timeline.
  • A professional ticket has four mandatory sections: summary, timeline, evidence, and actions taken. Every claim must reference a specific log entry with a timestamp and field values.
  • The escalation trigger is simple: if the attack succeeded in any form (successful login, SQLi returning data, exfiltration bytes), escalate to Tier-2 and notify CISO if data loss is possible.
  • Close tickets with recommended remediation. An incident that is contained but not remediated will happen again.
