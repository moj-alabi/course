Chapter 10

Detecting Abnormal Traffic

Baselines, thresholds, statistical anomalies, and behavioural rules. How Sophos IPS and Wazuh identify threats in a sea of normal traffic.

Learning Objectives

  • Define what a traffic baseline is and why it matters
  • Explain signature-based vs anomaly-based detection and when each is used
  • Describe the Sophos IPS signature library and how severity levels are assigned
  • Read a Wazuh composite rule and understand how frequency-based alerting works
  • Identify the key indicators for each major attack category in logs

What is Normal? Building a Baseline

You cannot detect abnormal traffic without first knowing what normal looks like. A baseline is a statistical picture of your environment during typical operations: how many connections per minute, which ports are commonly used, which external IPs appear regularly, what the typical data transfer volumes are.

Baseline knowledge lets you immediately spot anomalies: a server that never made outbound connections suddenly contacting an external IP, a workstation uploading 500 MB at 2am, DNS queries at a rate ten times higher than usual from a single host.

Signature-Based vs Anomaly-Based Detection
Both approaches are necessary. Signature detection catches known attacks reliably. Anomaly detection catches novel threats and insider activity.

Sophos IPS: How Signatures Work

The Sophos IPS (Intrusion Prevention System) inspects network traffic against a library of thousands of signatures. Each signature has a unique ID, a severity level, and a recommended action (Alert, Drop, or Block).

Sophos IPS SeverityNumeric RangeExample SignatureTypical Action
Critical9-10Exploit kit, active ransomware C2Block (source IP blocked for duration)
High7-8Port scan, SQLi attempt, RCE attemptDrop (packet dropped, connection reset)
Medium4-6Protocol anomaly, unusual TLS versionAlert (log and allow)
Low1-3Informational, policy violationAlert
IPS Action vs Firewall Action
A Sophos IPS "Drop" only discards the offending packet. The TCP connection may continue. A Sophos IPS "Block" adds the source IP to a temporary block list, rejecting all further traffic from that IP for a configurable period. A Firewall "Deny" is a static policy rule that permanently blocks matching traffic based on IP/port/protocol.

Wazuh Frequency-Based Rules

Wazuh can detect attacks that are only visible when you look at many events together. A single failed SSH login (rule 5710, level 5) is not an alert worth escalating. But eight failures in sixty seconds from the same source (rule 5712, level 10) is a brute force attack.

This is done with frequency rules: a child rule that counts how many times its parent rule has fired for the same grouping field (usually srcip) within a time window.

Wazuh Rule Definition - Brute Force Detection
<!-- Parent rule: single SSH failure (level 5, no alert by default) --> <rule id="5710" level="5"> <match>Failed password</match> <description>SSH authentication failed</description> </rule> <!-- Child rule: 8 failures from same IP in 60s = brute force (level 10, fires alert) --> <rule id="5712" level="10"> <if_matched_sid>5710</if_matched_sid> <same_source_ip/> <!-- group by source IP --> <frequency>8</frequency> <!-- 8 times --> <timeframe>60</timeframe> <!-- within 60 seconds --> <description>SSHD brute force trying to get access to the system</description> </rule>

Key Takeaways

  • You cannot detect abnormal without knowing normal. Spend time understanding baseline traffic volumes, common ports, and typical connection patterns before investigating alerts.
  • Signature-based detection (Sophos IPS, Wazuh rules) catches known attacks reliably with low false positives. Anomaly-based detection catches novel attacks but generates more noise.
  • Wazuh frequency rules aggregate events over time windows. A level-10 alert from rule 5712 means the brute force threshold was crossed, not just that one failed login occurred.
  • The attack indicator table in this chapter is your quick-reference during investigations. Cross-reference the tool, the fields, and the values to confirm or rule out each category.
