Chapter 07

When HTTP Becomes HTTPS

TLS handshakes, certificate chains, what Sophos SSL inspection can reveal, and what Bettercap can expose. Understanding what defenders can and cannot see in encrypted traffic.

Learning Objectives

  • Explain what TLS does and why HTTPS is not the same as "safe"
  • Trace the TLS handshake step by step and identify what is visible at each stage
  • Understand what a certificate chain is and how browsers validate it
  • Describe what Sophos SSL inspection does and what it reveals to defenders
  • Explain what Server Name Indication (SNI) is and why it is visible even in encrypted traffic
  • Preview how Bettercap performs HTTPS stripping in Chapter 15
  • Read TLS-related log fields from Sophos and Wazuh

What TLS Actually Does

TLS (Transport Layer Security) is the protocol that encrypts traffic between a browser and a server. When a URL starts with https://, all the HTTP content you learned about in the previous three chapters is wrapped inside a TLS encryption layer before it leaves your machine.

TLS provides three things: confidentiality (only the two parties can read the data), integrity (the data cannot be changed in transit without detection), and authentication (you can verify you are talking to the real server, not an impostor).

HTTPS Does Not Mean Safe
HTTPS only means the connection between the browser and the server is encrypted. It says nothing about whether the server itself is legitimate, whether the page contains malware, or whether the application has security vulnerabilities. Phishing sites routinely use HTTPS with valid certificates. Malware C2 servers use HTTPS. Your WAF (SafeLine) and firewall (Sophos) need SSL inspection to see inside encrypted traffic.

The TLS Handshake Step by Step

Before any encrypted HTTP data flows, the browser and server run a TLS handshake to agree on encryption parameters and verify identities. This handshake itself is partially visible on the wire, which is why defenders can extract useful intelligence even from encrypted traffic without breaking encryption.

TLS 1.3 Handshake Timeline
The TLS handshake establishes encrypted communication. Steps 1 and 2 are visible in plaintext and contain useful intelligence: the SNI (hostname) and the server certificate.

What Is Visible Without SSL Inspection

Even without decrypting TLS traffic, Sophos and Wazuh can extract the following fields from the handshake packets:

Certificate Chains: How Trust Works

A TLS certificate is a digital document signed by a trusted authority that proves a server is who it claims to be. Your browser trusts certificates because they chain back to a root certificate authority (Root CA) that is pre-installed in your operating system.

Certificate Chain - From Root CA to End Entity
The certificate chain must trace back to a root CA trusted by the browser's OS. A break in the chain, an expired certificate, or an unknown root CA all cause browser warnings.

Sophos SSL Inspection

By default, Sophos cannot read the content of HTTPS traffic because it is encrypted. SSL inspection (also called TLS interception or SSL decryption) is a feature where Sophos acts as a man-in-the-middle between the browser and the server. It decrypts the traffic, inspects it, then re-encrypts it before forwarding.

For SSL inspection to work without browser warnings, the Sophos firewall's own certificate must be installed as a trusted CA on all managed devices. This is typically done via group policy in enterprise environments.

Sophos SSL Inspection Architecture
Sophos acts as a transparent TLS proxy. It maintains two separate encrypted sessions and reads plaintext in the middle. SafeLine WAF downstream also sees decrypted traffic.

What Bettercap Does to HTTPS (Preview of Chapter 15)

In Chapter 15 you will run a live HTTPS stripping attack using Bettercap. Here is a conceptual preview so you understand what to expect.

HTTPS stripping is an attack where the attacker intercepts the connection between the browser and server and downgrades the browser's connection from HTTPS to HTTP, while maintaining an HTTPS connection to the real server. The victim's browser thinks it is on a normal HTTP page and transmits credentials in plaintext that the attacker can read.

HTTPS Stripping Attack vs Normal HTTPS (Preview)
In an HTTPS stripping attack, the victim's browser communicates over plain HTTP to the attacker, who relays the traffic to the real server over HTTPS. The victim's credentials are visible to the attacker.

Key Takeaways

  • HTTPS encrypts traffic but does not guarantee the server is safe or legitimate. Attackers use HTTPS just as commonly as defenders.
  • The TLS handshake leaks two key pieces of intelligence in plaintext: the SNI (hostname) and the server certificate. These are always available without SSL inspection.
  • Sophos SSL inspection decrypts HTTPS, inspects the HTTP content, then re-encrypts. This requires the Sophos certificate to be trusted on managed endpoints.
  • The JA3 fingerprint identifies the TLS client software. It is consistent across connections from the same tool or malware family and is a powerful detection signal.
  • HTTPS stripping attacks downgrade the browser connection to plain HTTP. Wazuh can detect the underlying ARP spoofing, and Sophos can log unexpected plain HTTP on port 443.
  • Key TLS log fields: sni, cert_issuer, tls_version, ja3, ssl_inspected. Always check SNI against threat intelligence, even for allowed connections.
