Wazuh Alert Levels: The Priority Scale

Every Wazuh alert has a level from 1 to 15. This number controls whether the alert appears in the queue, triggers a notification, or fires an active response. Understanding the level ranges is the first thing to check when triaging an alert.

Wazuh Alert Level Scale
Wazuh levels drive your response priority. Configure your Grafana alert panel to highlight level 10+ in red. By default, Wazuh only displays level 3+ in the alerts view.

The Decoder Pipeline

When a raw log line arrives at the Wazuh manager, it passes through a decoder pipeline before being matched against rules. The decoder extracts named fields from the raw text. Without a decoder, the rules engine can only match on the full raw string, which is far less reliable.

Wazuh Decoder Pipeline
The decoder runs before rules. If a log source has no decoder, fields like srcip will be empty and frequency rules that group by source IP will not work.

Complete Wazuh Alert JSON Schema

This is a realistic, fully populated Wazuh alert as it appears in OpenSearch. Every field an analyst may need to query is labelled.

Full Wazuh Alert JSON - SSH Brute Force (Rule 5712)
{ "timestamp": "2026-09-20T10:22:14.412+0000", "rule": { "id": "5712", "description": "SSHD brute force trying to get access to the system", "level": 10, "groups": ["syslog", "sshd", "authentication_failures"], "mitre": { "technique": ["T1110"], "tactic": ["Credential Access"] } }, "agent": { "id": "003", "name": "web-server-01", "ip": "10.0.1.10" }, "manager": { "name": "wazuh-manager" }, "data": { "srcip": "10.0.2.99", "dstuser": "admin", "dstport": "22", "protocol": "ssh2" }, "full_log": "Sep 20 10:22:14 web-server-01 sshd[4421]: Failed password for admin from 10.0.2.99 port 54821 ssh2", "location": "/var/log/auth.log", "decoder": { "name": "sshd" } }
Field PathTypeAnalyst Use
timestampISO 8601 datetimeUse to correlate with Sophos and SafeLine events. Always convert to UTC first.
rule.idstringLook up in Wazuh rule documentation for context. Filter by rule.id to find all instances.
rule.levelinteger 1-15Your primary triage indicator. Alert on level 10+. Review level 7-9 daily.
rule.groupsstring arrayUse to filter by category (e.g. authentication_failures, syscheck, web_log).
rule.mitre.techniquestring (MITRE ATT&CK ID)Maps the alert to the ATT&CK framework. T1110 = Brute Force. Use for threat reports.
agent.namestringWhich managed host generated the alert. Cross-reference with your asset inventory.
agent.ipIP addressThe host where the event occurred. Not the attacker IP.
data.srcipIP addressThe attacker source IP. This is what you search for in Sophos logs. Check against threat intel.
data.dstuserstringThe username being attacked. Check if this account has elevated privileges.
full_logstringThe original raw log line before decoding. Useful when decoded fields are missing.
locationfile pathWhich log file on the agent this came from. Useful for verifying the source is trusted.
decoder.namestringWhich decoder parsed this event. If "unknown", the event was not decoded and fields are missing.

File Integrity Monitoring (FIM) Alerts

Wazuh's FIM module takes a hash of every monitored file and compares it at regular intervals. Any change - permissions, owner, content - generates a FIM alert. FIM is critical for detecting malware dropping new files, attackers modifying configuration files, and supply chain compromise of system binaries.

Wazuh FIM Alert - Modified Binary (High Severity)
{ "timestamp": "2026-09-20T11:55:01.002Z", "rule": { "id": "550", "description": "Integrity checksum changed", "level": 7, "groups": ["syscheck"] }, "syscheck": { "path": "/usr/bin/python3", "event": "modified", "sha256_before": "a1b2c3d4...", "sha256_after": "deadbeef...", "uname_before": "root", "uname_after": "root", "inode_before": 45231, "inode_after": 98765 }, "agent": { "name": "web-server-01" } }
Responding to a Modified System Binary
A change to /usr/bin/python3 or any file in /bin or /usr/bin is a critical indicator of compromise. Immediately: (1) isolate the host from the network, (2) take a memory image if possible, (3) compare the new SHA256 hash against a known-good baseline or the package manager, (4) check /var/log/auth.log for logins around the time of the change, (5) do not reboot the host until you have a memory image.

Key Takeaways

  • Wazuh levels 1-6 are informational and low priority. Levels 7-9 need investigation in the current shift. Levels 10-12 need immediate escalation. Levels 13-15 may trigger automated responses.
  • The decoder pipeline runs before rules. If a log source has no decoder, the srcip field will be empty and frequency rules will not group events correctly.
  • The full Wazuh alert JSON contains rule metadata, MITRE ATT&CK mappings, agent information, decoded fields, and the original raw log line. The raw full_log field is the fallback when decoded fields are missing.
  • FIM alerts on system binary paths (/bin, /usr/bin, /etc) are high-severity indicators of compromise. Treat them as active incidents.
  • Learn the five OpenSearch queries that cover 90% of investigations: by level range, by source IP, by rule ID, by agent name, and by time window.
