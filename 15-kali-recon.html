Chapter 15

Kali Recon Toolkit

Using nmap, gobuster, nikto, and Wireshark to perform controlled reconnaissance in the lab network and observing how each generates distinct signatures in Wazuh, Sophos, and SafeLine logs.
Lab Environment Only
All tools in this chapter are used exclusively against the isolated lab network. Running these tools against any system you do not own or do not have explicit written permission to test is illegal in most jurisdictions. The lab network is the only authorised target.

Learning Objectives

  • Run a TCP SYN scan with nmap and observe the resulting Sophos IPS alert
  • Run a directory scan with gobuster and observe the SafeLine WAF log entries
  • Run nikto and identify the User-Agent in SafeLine logs
  • Capture nmap traffic in Wireshark and identify the TCP SYN scan pattern in packets
  • Correlate the attacker activity across all three tools in the logs

Tool 1: nmap - Network and Port Scanning

nmap is the standard tool for discovering hosts and open ports on a network. A TCP SYN scan (the default) sends SYN packets to each target port and reads the response. SYN/ACK = port open. RST = port closed. No response = filtered by firewall.

TCP SYN Scan Packet Pattern (nmap -sS)
nmap sends SYN packets to each port. It does not complete the three-way handshake (no ACK), which is the signature Sophos IPS detects as a TCP SYN scan.

Lab Command and Expected Log Output

# Lab exercise command (run from Kali VM only) $ nmap -sS -p 1-1000 10.0.1.10 # Expected output in Sophos IPS log: log_type="IPS" signature_name="TCP SYN Port Scan" severity="High" src_ip=10.0.2.99 dst_ip=10.0.1.10 action=Drop # Expected output in Wazuh: rule.description="Sophos: TCP SYN Port Scan detected" rule.level=9 data.srcip=10.0.2.99

Tool 2: gobuster - Web Directory Enumeration

gobuster tries to find hidden directories and files on a web server by requesting paths from a wordlist. It fires hundreds of requests per second, which is immediately visible in SafeLine WAF logs as a mass of 404 responses.

# Lab exercise command $ gobuster dir -u http://10.0.1.10 -w /usr/share/wordlists/dirb/common.txt # What SafeLine WAF sees in logs (sample, many similar entries): { "src_ip": "10.0.2.99", "method": "GET", "url": "/.htaccess", "status_code": 404, "user_agent": "gobuster/3.6", "attack_type": "scanner", "action": "block" } # gobuster identifies itself in User-Agent. SafeLine blocks it as a scanner. # Signals: 100s of 404s/second from same IP, sequential common paths

Tool 3: nikto - Web Vulnerability Scanner

nikto is a web server scanner that tests for thousands of known vulnerabilities, misconfigurations, and outdated software. Like gobuster, its User-Agent string identifies it immediately in WAF logs.

Tool 4: Wireshark - Capturing and Reading the Scan Traffic

Wireshark is a packet capture tool that shows every packet on the network in real time. Running it alongside nmap lets you see exactly what the TCP SYN scan looks like at the packet level, reinforcing everything you learned in Chapters 01-03.

Wireshark Display Filter for nmap SYN Scan Traffic
# Capture filter: only see traffic from the nmap host host 10.0.2.99 # Display filter in Wireshark: show only SYN packets (no ACK) - the scan tcp.flags.syn == 1 and tcp.flags.ack == 0 # Display filter: show SYN/ACK responses (open ports) tcp.flags.syn == 1 and tcp.flags.ack == 1 and ip.src == 10.0.1.10 # What you will see: # 10.0.2.99 -> 10.0.1.10 TCP 10.0.2.99:54821 -> 10.0.1.10:22 [SYN] # 10.0.1.10 -> 10.0.2.99 TCP 10.0.1.10:22 -> 10.0.2.99:54821 [SYN, ACK] <- port 22 OPEN # 10.0.2.99 -> 10.0.1.10 TCP 10.0.2.99:54822 -> 10.0.1.10:23 [SYN] # No response for port 23 (filtered)
Connecting Packets to Log Entries
When you run Wireshark alongside the Grafana dashboard, you can see the alert appear in Grafana within 5-10 seconds of the first SYN packets arriving. The same src_ip (10.0.2.99) appears in the Wireshark capture, the Sophos IPS log, and the Wazuh alert JSON. This is the cross-tool correlation you practise in the hands-on labs.

Key Takeaways

  • nmap SYN scans generate a distinctive pattern in Sophos IPS logs: many SYN packets to sequential ports from the same source IP in a short time window, matching signature 18487.
  • gobuster and nikto both identify themselves in their User-Agent strings by default. SafeLine WAF blocks them as scanners immediately. Real attackers change their User-Agents.
  • Wireshark display filters let you isolate specific packet types. tcp.flags.syn == 1 and tcp.flags.ack == 0 shows only outgoing scan packets. SYN/ACK responses reveal which ports are open.
  • The most important lab skill is cross-tool correlation: seeing the same src_ip appear in Wireshark, Sophos IPS logs, SafeLine WAF logs, and Wazuh alerts simultaneously.
