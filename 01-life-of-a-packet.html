Chapter 01

The Life of a Packet

From application to wire and back again. The OSI model explained in plain English, with every layer mapped to the tools and attacks that operate there.

Learning Objectives

  • Explain what a packet is and why data is split into packets at all
  • Name all seven OSI layers and describe in one sentence what each one does
  • Identify which layer each tool in this course operates at (Sophos, SafeLine, Wazuh, Wireshark)
  • Explain why the layer an attack targets determines which tools can detect and stop it
  • Describe what encapsulation means and how it relates to headers
  • Use the OSI model as a diagnostic framework when a network problem or attack is reported

What is a Packet?

Imagine you want to send a large book to a friend by post. You cannot fit the whole book in one envelope, so you tear out each page, put each page in its own numbered envelope, and post them all separately. Your friend receives the envelopes in any order, uses the numbers to sort them, and reassembles the book. A packet is the digital equivalent of one of those envelopes.

When you load a web page, your computer does not send one giant blob of data. It breaks the request into small chunks called packets, each typically between 40 and 1500 bytes in size. Each packet travels independently across the network, may take a different route, and is reassembled at the destination. This approach has three major advantages:

  • Reliability: If one packet is lost in transit, only that packet is re-sent, not the entire message.
  • Efficiency: Many users can share the same network links simultaneously because packets from different conversations interleave freely.
  • Resilience: Packets can route around failures automatically because each one finds its own path.
Why This Matters to an Analyst
When you look at a capture in Wireshark, you are looking at individual packets. When you read a Sophos firewall log, each row represents a decision made about one packet or flow. Understanding that all network data is broken into packets is the foundational concept everything else in this course builds on.

The OSI Model: The Master Reference

The OSI model (Open Systems Interconnection model) is a framework that divides the job of "sending data across a network" into seven separate layers. Each layer has one specific job. Each layer only talks to the layers directly above and below it.

Think of it like a postal service. There are people who write letters (Layer 7, the application), people who put letters in envelopes (Layer 6), people who sort the envelopes by postcode (Layer 3), people who drive the vans (Layer 2), and the actual roads the vans drive on (Layer 1). Each person has one job and does not need to know the details of every other job.

The model matters to security analysts because different attacks target different layers, and different tools defend different layers. Knowing which layer an attack operates at immediately tells you which evidence to look for and which tool will have seen it.

The Seven Layers Explained

Here is each layer in plain English, with the detail an analyst actually needs.

Layer 7
Application
The program itself. The human-readable content. This is what the user actually sees and what the attacker actually wants. A web browser is a Layer 7 application. When you type a URL and press Enter, your browser creates an HTTP request at Layer 7. The content of that request (the URL path, the query string, the form fields) is the Layer 7 data. SQL injection attacks, cross-site scripting, and directory brute force are all Layer 7 attacks because they abuse the application's logic using valid protocol messages. The SafeLine WAF and Wazuh are your primary Layer 7 defenders.
Layer 6
Presentation
How data is formatted, encoded, and encrypted. Layer 6 is responsible for turning application data into a format suitable for transmission and back again. TLS (the protocol that makes HTTPS work) lives here. When you see the padlock in your browser, Layer 6 is encrypting your data. The practical security implication: encryption happens at Layer 6, which means a firewall operating at Layer 3 or 4 cannot read the contents of HTTPS traffic. Sophos uses SSL inspection to decrypt and re-inspect this layer, which is how it can enforce policy on encrypted web traffic.
Layer 5
Session
Managing the start, middle, and end of a conversation. Layer 5 keeps track of which response goes with which request, and keeps multiple streams of data from getting mixed up. In practice, Layers 5, 6, and 7 are often bundled together in modern protocols. Session hijacking attacks (stealing an authenticated session cookie to impersonate a logged-in user) target this layer. Wazuh authentication logs will show session creation and destruction events.
Layer 4
Transport
Port numbers. Reliability. TCP vs UDP. Layer 4 adds port numbers to packets so the receiving host knows which application to hand the data to. Port 22 goes to SSH, port 80 to HTTP, port 443 to HTTPS. TCP (the protocol covered in Chapter 03) is the most common Layer 4 protocol. It guarantees delivery by using the three-way handshake and sequence numbers. UDP sends packets without any guarantee. SYN flood attacks (sending millions of half-open TCP connections to overwhelm a server) are Layer 4 attacks. Port scanning is Layer 4 reconnaissance. The Sophos IPS engine and Wazuh network rules operate primarily at Layers 3 and 4.
Layer 3
Network
IP addresses. Routing. Getting packets across the internet. Layer 3 adds source and destination IP addresses to each packet. Routers (including your Sophos firewall acting as a router) operate at Layer 3. They look at the destination IP address of each packet and decide which path to send it down. IP spoofing (forging the source IP address in a packet) is a Layer 3 attack. The Sophos firewall policy engine is primarily a Layer 3/4 tool: it allows or denies traffic based on source IP, destination IP, and port.
Layer 2
Data Link
MAC addresses. Local network delivery. ARP. Layer 3 routes packets across the internet using IP addresses. But once a packet arrives on your local network, it needs a different address to find the right device on that specific segment. That is the MAC address (also called hardware address or Ethernet address). Every network card has a unique MAC address burned in at the factory. ARP (Address Resolution Protocol) is the Layer 2 mechanism that maps an IP address to a MAC address. ARP spoofing is a Layer 2 attack: the attacker sends forged ARP replies to redirect traffic to their machine. Sophos firewall cannot block ARP spoofing because it operates at Layer 3 and never sees Layer 2 frames. Wireshark can see it because it captures at Layer 2.
Layer 1
Physical
The wire. The radio signal. The electrons. Layer 1 is the actual physical medium carrying the signal: copper cable, fibre optic, Wi-Fi radio waves. Security at this layer means physical access controls (locked server rooms, cable management). This is out of scope for this course. All tools and attacks covered here operate at Layers 2 through 7.

Encapsulation: How Layers Wrap Each Other

Encapsulation is the process of wrapping data with the header information needed by each layer. When you send an HTTP request, here is what actually happens step by step on your computer before the packet hits the wire:

Encapsulation: A Web Request Being Wrapped Layer by Layer
Each layer adds its own header around the data from the layer above. This is encapsulation. At the receiving end, each layer removes its header and passes the remaining data upward. Wireshark shows you all of these headers at once, which is why it can dissect every layer of a packet.

When the destination host receives the packet, the process runs in reverse. The network card strips the Ethernet header (Layer 2), hands the remaining data up. The operating system strips the IP header (Layer 3), hands it up. The TCP stack strips the TCP header (Layer 4), hands it up. The web server application receives the original HTTP request (Layer 7). This reverse process is called decapsulation.

Where Your Tools Sit in the Stack

Every tool in this course captures data at a specific layer. A tool cannot see data at layers below the one it operates at. This is the single most important thing to understand about your defensive tool stack.

Tool Positions in the OSI Stack
Each tool covers a different section of the OSI stack. Wireshark is the most complete because it captures raw frames. SafeLine sees only Layer 7. Sophos covers Layers 3-7 but cannot see below Layer 3. Wazuh sees Layers 4-7 but only through logs, not raw packets. Grafana is a presentation tool that visualises data from all other tools.

Why the OSI Layer an Attack Targets Matters

Here is a worked example that illustrates why OSI layer knowledge is critical for a security analyst.

Scenario: You receive a Wazuh alert saying a victim host's traffic is being intercepted. The suspected attack is ARP spoofing.

QuestionAnswer Using OSI Layer Knowledge
What layer is ARP spoofing? Layer 2 (Data Link). ARP is a Layer 2 protocol that maps IP addresses to MAC addresses.
Can Sophos firewall block it? No. Sophos operates at Layer 3 and above. It never processes Layer 2 frames. ARP packets are invisible to it.
Can Wireshark see it? Yes. Wireshark captures at Layer 2, which includes all ARP traffic. It will also flag duplicate ARP replies as a warning.
What evidence will Wazuh have? Wazuh can detect ARP spoofing via Suricata or via an agent-based ARP monitoring rule. It will produce an alert with the conflicting MAC addresses. But it learns about this via a log from another tool, not by seeing the raw ARP packet itself.
What evidence will SafeLine have? None about the ARP spoofing itself. SafeLine is Layer 7. If the attacker then injects content into the victim's HTTP traffic, SafeLine might see unusual HTTP requests, but it cannot see the Layer 2 mechanism that made the attack possible.
How do you stop it? Dynamic ARP Inspection (DAI) on the network switch. This is a Layer 2 control on the switch itself. None of the tools covered in this course implement DAI (it is a switch feature), but Wazuh can alert on it happening.
The Analyst Diagnostic Pattern
When you receive an alert about an attack, always ask: "What OSI layer is this attack operating at?" Then ask: "Which of my tools operates at that layer?" That tells you immediately which tool has the evidence and which tools are blind to this particular threat. This framework appears in every chapter of this course.

Key Takeaways

  • A packet is a small chunk of data with addressing headers attached. All network data is broken into packets and reassembled at the destination.
  • The OSI model has 7 layers. Each layer has one job. Layer 1 is the physical wire. Layer 7 is the application. Layers go from hardware at the bottom to software at the top.
  • Encapsulation wraps data from higher layers with headers from lower layers. Decapsulation strips those headers at the receiving end. Wireshark shows you every layer simultaneously.
  • The layer an attack targets determines which tool can see it. ARP spoofing is Layer 2 - Sophos cannot see it. SQL injection is Layer 7 - SafeLine is the primary defence. Port scanning is Layer 4 - Sophos IPS and Wazuh both see it.
  • Wireshark is the only tool in this course that captures at Layer 2, making it the most complete source of evidence but also the most demanding to interpret.
  • When you receive any alert in this course, always identify the OSI layer first. That one step tells you which tools have evidence, which are blind, and what to look for.
