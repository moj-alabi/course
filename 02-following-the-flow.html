Chapter 02

Following the Flow

How a packet actually gets from your laptop to a web server across the internet. MAC addresses, IP addresses, ARP, DNS, gateways, and routing - explained step by step with every field labelled.

Learning Objectives

  • Explain the difference between a MAC address and an IP address and why both are needed
  • Describe what ARP does and why it is necessary
  • Explain how DNS translates a domain name into an IP address
  • Trace the journey of a packet from a browser to a web server, naming every step
  • Read a Sophos firewall flow log entry and identify every field
  • Read a Wazuh network event alert and identify every field
  • Identify the OSI layer each protocol operates at and explain why that matters for detection

Two Types of Address: MAC vs IP

Before we can trace the journey of a packet, we need to understand that every packet carries two completely different types of address, and each one serves a different purpose.

Layer 2 MAC Addresses - For Local Delivery

A MAC address (Media Access Control address, also called hardware address or Ethernet address) is a 48-bit identifier burned into every network card at the factory. It looks like this: 00:1A:2B:3C:4D:5E. The first three pairs of characters (the OUI, Organisationally Unique Identifier) identify the manufacturer. The last three pairs are a unique serial number.

MAC addresses operate at Layer 2 (Data Link). They are only meaningful on your local network segment. When a packet leaves your local network and crosses a router, the Ethernet frame (and its MAC address) is stripped off and a new one is created for the next segment. By the time a packet from your laptop reaches a web server in another country, the original MAC address you sent it with is long gone.

Why this matters for an analyst: MAC addresses in logs tell you which physical device on your local network sent traffic. An attacker who forges a MAC address (MAC spoofing) can bypass MAC-based access controls. An attacker who sends forged ARP replies (ARP spoofing, covered below) can misdirect local traffic at Layer 2 in a way that Sophos firewall (which operates at Layer 3) cannot see.

Layer 3 IP Addresses - For Internet-Wide Routing

An IP address is a logical address assigned to a device by a network administrator or DHCP server. It is not burned into hardware and can be changed. An IPv4 address looks like: 192.168.1.45. It is 32 bits, written as four decimal numbers (octets) separated by dots, each between 0 and 255.

IP addresses operate at Layer 3 (Network). Unlike MAC addresses, they survive the entire journey across the internet. Routers use the destination IP address to decide where to forward each packet. The source IP address is the ultimate origin of the communication and is the primary identifier in firewall logs, Wazuh alerts, and SafeLine WAF blocks.

Layer 2 ARP: How MAC Meets IP

Here is the problem: your computer needs to send a packet to an IP address on your local network. But Ethernet delivers frames using MAC addresses, not IP addresses. So how does your computer find out which MAC address belongs to the IP address it wants to reach?

The answer is ARP (Address Resolution Protocol). ARP is a simple question-and-answer protocol. Your computer broadcasts the question "Who has IP address X?" to every device on the local network. The device that owns that IP address replies with "I have it, and my MAC address is Y." Your computer then caches this mapping so it does not have to ask again for a few minutes.

ARP: How MAC Addresses Are Resolved from IP Addresses
The ARP broadcast goes to every device on the local network (destination MAC FF:FF:FF:FF:FF:FF means "everyone"). Only the device that owns the queried IP replies. The reply goes only to the requester. Your computer caches the result to avoid asking again every time.

ARP Spoofing: Why Layer 2 Matters for Attackers

ARP has no authentication. Any device on the network can send an ARP reply claiming any IP address. An attacker running Bettercap can continuously broadcast fake ARP replies saying "10.0.0.1 (the gateway) is at MY MAC address". Every device on the network updates its ARP cache with the wrong mapping. Now all traffic intended for the gateway flows to the attacker first. This is a Layer 2 attack and is invisible to Sophos firewall because Sophos operates at Layer 3 and never processes raw ARP frames.

Wireshark will show you duplicate ARP replies with conflicting MAC addresses. Chapter 16 covers this in full with lab evidence from Bettercap.

Layer 7 DNS: Translating Names to Addresses

Humans remember names like www.bank.com. Routers route by IP address. DNS (Domain Name System) is the global phonebook that translates one into the other.

DNS is technically a Layer 7 (Application) protocol, but it uses UDP at Layer 4 (port 53). DNS queries happen before any other network activity - you cannot connect to a web server until you know its IP address.

DNS Resolution: Turning a Name into an IP Address
A full DNS resolution. Steps 2-4 happen inside the recursive resolver - the resolver caches the answer so most queries skip steps 2-4 entirely. The TTL (Time to Live) field tells the resolver how many seconds to cache the answer before asking again.

DNS Log Fields - Wazuh Example

DNS queries appear in Wazuh as events decoded from the Sophos firewall's DNS log or from a DNS server agent. Here is what a DNS query event looks like with every field explained:

Wazuh DNS Event - Normal Query (JSON format)
{ "timestamp": "2026-09-20T10:22:14.412Z", /* when the query happened (UTC) */ "rule": { "id": "86601", /* Wazuh rule number - 86xxx = DNS events */ "description": "DNS query", "level": "3" /* level 3 = informational, not a threat */ }, "agent": { "name": "sophos-firewall" /* which device produced this log */ }, "data": { "srcip": "10.0.2.5", /* which internal device made the query */ "query": "www.bank.com", /* the name being looked up */ "query_type": "A", /* A = IPv4 address lookup. AAAA = IPv6. MX = mail server */ "answer": "185.60.216.35", /* the IP address returned */ "response_code": "NOERROR", /* success. NXDOMAIN = domain does not exist */ "ttl": "300" /* cache for 300 seconds before asking again */ } }
Why DNS Logs Matter to an Analyst
Malware often uses DNS to find its command-and-control server. A compromised host calling out to a newly registered domain, a domain with many random characters (DGA - Domain Generation Algorithm), or a domain on a threat intelligence blocklist is a major indicator of compromise. Wazuh can correlate DNS queries against threat feeds and fire alerts when a match is found.

Ports: Which Service Gets the Packet

An IP address identifies a device. But a single device runs many services simultaneously. Port numbers at Layer 4 identify which service on that device should receive the packet.

Think of it like an office building. The IP address is the building address. The port number is the room number. You cannot just send a letter to the building - you need to know which room it is going to.

The Gateway: Your Exit from the Local Network

Every device on your local network has a default gateway configured. The gateway is the router that connects your local network to the internet (and to other networks). When your computer needs to send a packet to an IP address that is not on your local network, it sends the packet to the gateway first, and the gateway forwards it onwards.

In a home or office network, the gateway is typically your router. In a corporate network, the gateway is the Sophos firewall. This is why all internet traffic flows through Sophos - it is positioned as the gateway, and therefore every packet to or from the internet must pass through it.

Full Packet Journey: Browser to Web Server
The complete journey. DNS happens first (Step 0). ARP resolves the gateway MAC address (Step 2). Sophos inspects every packet at the boundary (Step 3). Routers forward the packet across the internet using the destination IP address only (Step 4). MAC addresses change at every router hop but IP addresses stay the same throughout.

Reading a Sophos Flow Log Entry

Every packet that passes through Sophos generates a log entry. Here is a real Sophos firewall log line for an outbound HTTPS connection, with every field explained:

Sophos Firewall Flow Log - Full Field Reference
date=2026-09-20 # date of the event time=10:22:14 # time of the event (local time on firewall) device_name=SFW-HQ-01 # hostname of the Sophos appliance log_id=010101600001 # unique log type identifier log_type=Firewall # type: Firewall, IPS, AppControl, WebFilter, SSL log_component=Firewall Rule # sub-component that generated this entry log_subtype=Allowed # Allowed or Denied status=Allow # Allow or Deny priority=6 # syslog priority level (6 = informational) duration=44 # how long the connection lasted, in seconds src_ip=10.0.2.5 # source IP: the device that initiated the connection src_mac=AA:BB:CC:DD:EE:FF # source MAC: physical hardware address of the source src_port=52341 # source port: randomly chosen ephemeral port src_zone=LAN # network zone the source is in dst_ip=185.60.216.35 # destination IP: the web server being contacted dst_port=443 # destination port: 443 = HTTPS dst_zone=WAN # network zone the destination is in protocol=TCP # transport protocol: TCP or UDP fw_rule_id=12 # which firewall policy rule made this Allow/Deny decision sent_bytes=4215 # bytes sent by source to destination recv_bytes=98442 # bytes received by source from destination sent_pkts=48 # packets sent recv_pkts=312 # packets received user_name=john.smith # authenticated user (if Sophos auth agent running) application=HTTPS # application identified by AppControl engine
What to Look For in Flow Logs
Normal outbound HTTPS: sent_bytes much lower than recv_bytes (you send a small request, receive a large page). If sent_bytes is much higher than recv_bytes, that is a data exfiltration indicator. A duration of hundreds of seconds with high sent_bytes to an unusual external IP should trigger an investigation.

Reading a Wazuh Network Alert

Wazuh receives the Sophos syslog and decodes it through its rule engine. Here is what a Wazuh alert looks like for a suspicious DNS query to a known malicious domain:

Wazuh Alert - DNS Query to Threat Intelligence Hit
{ "timestamp": "2026-09-20T10:44:02.887Z", "rule": { "id": "86603", "description": "DNS query to known malicious domain", "level": "12", /* level 12 = high severity - requires investigation */ "groups": ["dns", "threat_intel", "malware"] }, "agent": { "id": "003", "name": "sophos-firewall", "ip": "10.0.0.1" }, "data": { "srcip": "10.0.2.55", /* internal host making the query */ "query": "c2panel.xr7m3qa.xyz", /* suspicious-looking domain */ "query_type": "A", "answer": "185.220.101.45", /* resolved IP - check against threat intel */ "response_code": "NOERROR", "threat_feed_match": "EmergingThreats - C2" /* matched a threat intelligence feed */ }, "_source": { "srcip": "10.0.2.55", "location": "Sophos DNS Log", "full_log": "date=2026-09-20 time=10:44:02 ... dns_query=c2panel.xr7m3qa.xyz ..." } }

The key fields an analyst uses in triage are: srcip (which internal device is compromised), query (what domain it is calling), threat_feed_match (confirmation it is known malicious), and timestamp (when it started). These four fields answer the immediate questions: who, what, and when.

Key Takeaways

  • MAC addresses (Layer 2) are for local delivery within a network segment. They change at every router hop. IP addresses (Layer 3) are for global routing and stay the same end-to-end.
  • ARP (Layer 2) maps IP addresses to MAC addresses on the local network. It has no authentication, which is why ARP spoofing works. Sophos cannot see ARP because it operates at Layer 3 and above.
  • DNS (Layer 7 over UDP port 53) translates domain names into IP addresses before any connection can be made. DNS logs reveal what external services a host is communicating with and can catch malware C2 beaconing.
  • Port numbers (Layer 4) identify which service on a device should receive a packet. Unusual port usage - especially inbound connections to ports that should never receive inbound traffic - is a major detection signal.
  • The default gateway is the first hop for all non-local traffic. Sophos firewall acts as the gateway, which means every internet-bound packet passes through it and is logged.
  • Sophos flow logs contain srcip, dstip, dstport, protocol, duration, sent_bytes, recv_bytes. An unusual ratio of sent to received bytes, especially to an external IP, is an exfiltration indicator.
