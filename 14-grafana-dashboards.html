Chapter 14

Grafana Dashboards

How Grafana connects to Wazuh OpenSearch, how panels work, and how to build and read the security dashboards you will use throughout this course.

Learning Objectives

  • Explain how Grafana connects to Wazuh data via the OpenSearch data source
  • Identify the five dashboard panel types and when to use each one
  • Read a Grafana time-series panel and identify spikes that indicate attacks
  • Understand how Grafana alert rules work and what they generate
  • Describe the standard SOC dashboard layout used in this course environment
  • Build a basic panel query using the Lucene query syntax

How Grafana Connects to Wazuh

Grafana is a visualisation platform. It does not store data itself. Instead it connects to data sources and queries them on demand. In this course environment, Grafana queries the Wazuh OpenSearch index using the OpenSearch data source plugin.

Grafana Data Flow Architecture
Grafana never stores data. It queries OpenSearch each time a panel loads or refreshes. The OpenSearch index wazuh-alerts-* contains all Wazuh alert JSON documents.

Reading a Time Series Panel - Spotting an Attack Spike
A sudden spike in the alert count time series at 08:22 indicates a brute force attack. The baseline is around 2-5 alerts per 5-minute bucket. The spike hits 48. Clicking the spike opens the raw alert table.

Grafana Alert Rules

Grafana can evaluate panel queries on a schedule and fire alerts when conditions are met, sending notifications to email, Slack, PagerDuty, or webhook endpoints. This is how you receive out-of-hours notifications for critical events without watching the dashboard.

Alert Rule FieldExample ValuePurpose
ConditionIS ABOVE 5Threshold that triggers the alert. "Count of level-10 alerts IS ABOVE 5 in 5 minutes"
Evaluate every1mHow often Grafana checks the condition. More frequent = faster detection but more load
For2mHow long the condition must be true before the alert fires. Reduces false positives from transient spikes
StateFiring / Pending / NormalCurrent alert state. Firing = condition met. Pending = within "For" window. Normal = resolved.
Contact pointslack-soc-channelWhere to send the notification. Configure in Grafana Alerting settings.

Building a Basic Panel Query

Panel queries use the Lucene query language (same as OpenSearch). Here are the most useful queries for security panels.

# Count of high-severity alerts over time Query: rule.level:[10 TO 15] Metric: Count Group by: Date Histogram - @timestamp - 5 minutes # Top attacking IPs - bar chart Query: rule.level:[7 TO 15] Metric: Count Group by: Terms - data.srcip - Top 10 # Recent critical alerts - table Query: rule.level:[10 TO 15] Metric: Raw documents Columns: @timestamp, rule.id, rule.description, agent.name, data.srcip, rule.level Order by: @timestamp DESC

Key Takeaways

  • Grafana does not store data. It queries OpenSearch (which stores Wazuh alerts) and renders the results as visual panels. Data freshness depends on the refresh interval.
  • Use Time Series panels for attack volume trends and spike detection. Use Stat panels for at-a-glance numbers. Use Table panels for actionable alert lists.
  • A spike in the alert time series always warrants investigation. Click the spike period to filter the table panel to that time window and see the individual alerts.
  • Grafana alert rules fire notifications when conditions (such as more than 5 level-10 alerts in 5 minutes) are met. Configure these to receive out-of-hours incident notifications.
  • The standard Lucene query for critical alerts is: rule.level:[10 TO 15] with a Date Histogram aggregation for time series, or Terms aggregation on data.srcip for the top attacker bar chart.
