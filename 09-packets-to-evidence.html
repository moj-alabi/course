Chapter 09

From Packets to Evidence

How raw network data becomes structured log events, flows through the detection stack, and arrives as actionable alerts in Wazuh and Grafana.

Learning Objectives

  • Describe the full telemetry pipeline from packet capture to alert
  • Understand what Sophos flow records are and how they differ from raw PCAPs
  • Explain how Wazuh agents ship logs and how the manager processes them
  • Describe how Grafana queries Wazuh data for dashboards
  • Read a Wazuh agent configuration file and understand what it monitors

The Telemetry Pipeline

Every alert you see in a dashboard started as raw network traffic or a raw log line. Understanding how that data travels through the pipeline helps you know where to look when an alert is missing, delayed, or incorrect.

Full Telemetry Pipeline: From Wire to Dashboard
From raw packet to dashboard alert. Each stage transforms the data and adds structure that makes it queryable.

Sophos Flow Records vs Raw PCAPs

Sophos can generate two types of network evidence: flow records (NetFlow-style summaries) and raw packet captures (PCAP files).

TypeWhat It ContainsFile SizeBest Used For
Flow Recordsrc_ip, dst_ip, ports, protocol, byte counts, timestamps, actionVery small (one line per connection)Traffic analysis, anomaly detection, incident scoping
PCAPEvery raw packet including full payload (if not encrypted)Very large (can be GBs per hour)Deep forensic investigation, payload analysis, vulnerability reproduction
When to Request a PCAP
Request a Sophos PCAP capture when: (1) you need to see the exact payload of a suspicious connection, (2) you are investigating a potential data exfiltration and need to know what was sent, (3) you are reverse-engineering an attack and need the raw HTTP or command strings. Start with flow records for scoping, escalate to PCAP for evidence.

Wazuh Agent Architecture

A Wazuh agent is a lightweight service installed on every managed host. It reads configured log sources, monitors file integrity, checks running processes, and ships events to the Wazuh manager over an encrypted channel on port 1514.

Wazuh Agent to Manager Communication
Each agent ships events in real time. The manager decodes, correlates, and stores them. The analyst queries the stored data through Grafana or the Wazuh dashboard.

Key Wazuh Agent Configuration Fields

/var/ossec/etc/ossec.conf (agent configuration excerpt)
<!-- Log files to monitor --> <localfile> <log_format>syslog</log_format> <location>/var/log/auth.log</location> </localfile> <localfile> <log_format>apache</log_format> <location>/var/log/nginx/access.log</location> </localfile> <!-- File Integrity Monitoring --> <syscheck> <frequency>43200</frequency> <!-- check every 12 hours --> <directories check_all="yes">/etc,/bin,/usr/bin</directories> </syscheck>
Config KeyPurposeAnalyst Impact
localfile / locationPath to the log file the agent readsIf a log source is not listed here, Wazuh will not see events from it
log_formatParser to apply (syslog, apache, json, etc.)Wrong format = fields will not be extracted, searches will fail
syscheck / directoriesFile paths monitored for integrity changesChanges to binaries or config files in these paths generate FIM alerts
syscheck / frequencyHow often (seconds) to scan for file changesHigher frequency catches changes faster but uses more CPU

Key Takeaways

  • The pipeline is: raw traffic → Sophos inspection → Wazuh agent collection → Wazuh manager correlation → OpenSearch storage → Grafana visualisation.
  • Flow records give you connection metadata (who talked to whom, how much data). PCAPs give you the full payload. Start with flows, escalate to PCAP when needed.
  • Wazuh agents must be configured to monitor the right log files. If a source is not in the agent config, it will not appear in alerts.
  • End-to-end latency from event to alert is typically 5-30 seconds under normal load. High log volume can increase this delay.
